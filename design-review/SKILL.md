### Format

Every AskUserQuestion is a decision brief and must be sent as tool_use, not prose.

```
D<N> — <one-line question title>

  ❌ <con>
Net: <one-line synthesis of what you're actually trading off>
```

D-numbering: first question in a skill invocation is `D1`; increment yourself. This is a model-level instruction, not a runtime counter.

ELI10 is always present, in plain English, not function names. Recommendation is ALWAYS present. Keep the `(recommended)` label; AUTO_DECIDE depends on it.

Completeness: use `Completeness: N/10` only when options differ in coverage. 10 = complete, 7 = happy path, 3 = shortcut. If options differ in kind, write: `Note: options differ in kind, not coverage — no completeness score.`

Pros / cons: use ✅ and ❌. Minimum 2 pros and 1 con per option when the choice is real; Minimum 40 characters per bullet. Hard-stop escape for one-way/destructive confirmations: `✅ No cons — this is a hard-stop choice`.

Neutral posture: `Recommendation: <default> — this is a taste call, no strong preference either way`; `(recommended)` STAYS on the default option for AUTO_DECIDE.

Effort both-scales: when an option involves effort, label both human-team and CC+gstack time, e.g. `(human: ~2 days / CC: ~15 min)`. Makes AI compression visible at decision time.

Net line closes the tradeoff. Per-skill instructions may add stricter rules.

## Factorial Design Standards Reference

These are the standards to audit against. Every finding must cite which standard is violated.

### Typography
- **Font:** DM Sans only. No system fonts, no other Google Fonts.
- **Headings:** Bold (700) or Semi-bold (600). Never Regular for H1/H2.
- **Body:** Regular (400) or Medium (500) for emphasis.
- **Scale:** Use the design system type scale. No arbitrary `text-[Npx]` unless justified.
- **Line height:** 1.4–1.6 for body, 1.1–1.3 for headings. Tight headings look intentional.

### Color
- **Palette:** `neutral-*`, `radical-*` (brand red), `viridian-*` (teal), `sunbeam-*`, `tangerine-*`, `jade-*`.
- **No hardcoded hex.** All colors via design tokens.
- **Contrast:** Minimum 4.5:1 for body text, 3:1 for large text (WCAG AA).
- **Primary actions:** `radical` (brand red). Not blue, not generic.

### Spacing
- **System:** 4px grid. All spacing should be multiples of 4px.
- **Section padding:** Consistent across sibling sections (check top/bottom padding).
- **Component internal spacing:** Consistent with design-system component definitions.

### Animation
- **RevealOnScroll:** Standard reveal for sections. Elements above fold should NOT wait to reveal.
- **Duration:** 200–500ms for UI feedback, 500–800ms for scroll reveals. Nothing faster than 150ms (jarring) or slower than 1000ms (sluggish).
- **Easing:** `ease-out` for enters, `ease-in` for exits. No linear.
- **Lottie:** Files above the fold should have `autoplay` but lazy-load the file.

### Responsiveness
- Breakpoints: **375px** (mobile), **768px** (tablet), **1440px** (desktop).
- No horizontal overflow at any breakpoint.
- Touch targets ≥ 44px on mobile.
- Typography scales appropriately (mobile can be slightly smaller, but still readable).

### AI Slop Patterns (red flags)
- Generic stock-photo style illustrations
- Bland blue/grey color scheme (not Factorial brand)
- Symmetric, corporate-looking layouts with no visual tension
- "Card grid with icons and titles" as the only layout pattern
- Overuse of rounded-full pills for all tags
- Shadow overuse (every card has the same shadow)

## Rules

- **CSS-first.** Prefer styling changes over structural component changes.
- **One commit per fix.** Never bundle multiple design fixes.
- **Factorial standards, not generic.** Don't flag things that are fine by Factorial standards just because they'd be unusual elsewhere.
- **Three breakpoints.** Always test 375/768/1440.
- **Before/after screenshots.** Every fix needs visual evidence.
